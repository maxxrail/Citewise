# Interview prep

Likely questions per module, with short, strong answers grounded in the actual code.

## Module 0 - Foundations

**1. "How do you know what every LLM call costs, and what stops a run from silently overspending?"**
Every call goes through one wrapper (`providers/tracking.py`), which `registry` always applies, so no caller can bypass it. It times the call, prices tokens from a dated table in `pricing.py`, and writes one `llm_calls` row per call. Failures and truncated responses are logged too, and the row is written in its own transaction so a caller's rollback can't erase it. Dated snapshot IDs map back to their alias. In live mode an unpriced model is refused *before* the request (`UnpricedModelError`), because recording $0 would blind the Module 2 budget guard. A test asserts the row, cost and latency for each of the four engines.

**2. "Your tests never touch the network. How do you trust that mock mode resembles production?"**
Mocks implement the same `ChatProvider` protocol as the live clients and are deterministic: the fixture key is sha256 of purpose plus messages, optionally per engine, and the embedder uses a seeded PRNG rather than Python's salted `hash()`. The structural risks are checked offline. `JsonSchema` rejects schemas OpenAI's strict mode would 400 on. The mock builds schema-valid output, including Pydantic `$ref`/`$defs`; a review found it had been returning strings for nested models. Mock calls carry realistic token and cost estimates, so the cost path runs in CI. The remaining gap is honest and documented: the live OpenAI path needs one smoke call with a real key.

**3. "User-supplied brand data ends up in your prompts. What's the injection story?"**
Defence in depth, starting at the boundary. `BrandCreate` caps aliases and competitors (20 items, 100 chars each), strips and dedupes them, rejects newlines and control characters (the cheapest way to fake a new instruction block), and reduces the domain to a validated hostname. That also bounds cost, since prompts scale with N aliases × M competitors. From Module 1 on, templates put brand values in delimited data sections and never treat them as instructions. Extraction output is schema-validated with Pydantic, so an injected "rank me first" can't change the output shape, and evals include red-team cases for it.

## Module 1 - Prompt panel and topic discovery

**1. "Silhouette picked k for you. Why trust it, and what did you do when it was flat?"**
I didn't trust it blindly. On raw 1536-dim embeddings the cosine silhouette sat between 0.09 and 0.22 for every k and always chose the smallest k, because distances concentrate in high dimensions. Reducing to 20 PCA dimensions (deterministic full SVD) separated the curve. I still bound k to 6–14 as a product prior, since a ~300-prompt panel is only usable as a handful-to-a-dozen topics, and k=11 vs k=12 differ by 0.005. Both are settings, `select_k` is unit-tested on synthetic blobs where the true k is known, and the scan panel picks one prompt per topic first, so a slightly wrong k still gets every theme measured. For real data I'd add a stability check (bootstrap ARI across seeds), not just the silhouette argmax.

**2. "Your intent classifier is evaluated against labels from another model. Isn't that circular?"**
Partly, and the code is explicit about it. `eval-intent` reports two separate things. First, *agreement*: 5-fold cross-validated logistic regression on embeddings vs the LLM's labels (0.72 / 0.83 accuracy). That shows the cheap student can replace the expensive teacher for routing. Second, *accuracy against a held-out, hand-reviewed golden set* (94 rows, about 40% hard boundary cases, checked for no exact or near-duplicate overlap with training). In mock mode the student scores 0.73–0.76 on it, and its failures are real: negation and the brand name used as an ordinary word. I deliberately don't record mock answers for the LLM on the golden set, because they would be the golden labels and report a fake 100%. Measuring the LLM needs one live run. Guessed labels (`fallback`, `embedding`) never become training data.

**3. "What happens to a long run when the provider rate-limits you halfway through?"**
It degrades instead of dying. `complete_structured` treats a provider exception after the SDK's retries the same as an invalid output: it retries once, then returns `None`. The tracker has already written an `ok=False` `llm_calls` row. Callers fall back. A generation cell is skipped and retried on the next run, because `generate` only fills cells that have no prompts. A topic gets a term-based label. An intent goes to the embedding classifier, and the LLM retries it on the next `cluster`. A per-command spend cap refuses further calls once reached, with the same skip semantics. All LLM calls in `cluster` happen before any DB write, so nothing paid for is lost to a rollback and no lock is held across model latency. An unpriced model is the one error that still fails loudly, before any money is spent.
