# Design decisions

Format: **Decision** — why — alternative rejected.

- **Official APIs only, no UI scraping.** Stays within provider ToS and can be reproduced; API answers with web search on approximate consumer answers. Rejected: headless-browser scraping of chatgpt.com (fragile, against ToS). Limitation noted in README.
- **SQLite for tests, Postgres for dev/prod.** Tests run on Windows with no Docker. Rejected: testcontainers (slow and fiddly on Windows).
- **Embeddings stored as arrays in a regular column, similarity done in numpy.** Panel sizes are thousands, not millions. Rejected: pgvector (extra setup); revisit if scale grows.
- **Mock mode is the default.** CI and the public demo never spend money; fixtures make results deterministic.

## Module 0

- **OpenAI live adapter uses the Responses API, not Chat Completions.** OpenAI's docs (checked 2026-11-23) recommend Responses for new projects, and it returns web-search `url_citation` annotations that Module 2 needs. Rejected: Chat Completions (still supported, but older and weaker on tool and search output).
- **Mock calls record an estimated cost from the real model's price.** `llm_calls.provider = "mock"` marks them, but `cost_usd` is what the call would have cost live. Demos show realistic spend and the Module 2 budget guard can be tested offline. Rejected: cost 0 in mock mode (the cost path would never run in CI).
- **Mock fixtures are keyed by sha256(purpose, messages[, engine]), without the model.** Lookup tries the engine-specific key first, then the generic one, so the four engines give different mock answers and per-engine share of voice means something in CI. Mock rows record `provider = "mock:<engine>"`. Changing a model ID doesn't invalidate recorded fixtures. A missing fixture falls back to a deterministic placeholder, which is schema-valid when a JSON schema is requested, so new code works in mock mode before anyone records a fixture. Rejected: failing on a missing fixture (too much friction for every new prompt).
- **Mock embedder = sha256(text) seeds a PRNG, giving a Gaussian 1536-dim unit vector.** Stable across OSes and Python versions, unlike `hash()`, which is salted per process. Same shape as `text-embedding-3-small`.
- **Call tracking writes in its own session and never raises.** A caller's rollback can't erase a cost record, and a DB hiccup can't kill an LLM call. Failed calls are still logged (`ok=False`, error text) and then re-raised. Rejected: logging in the caller's transaction.
- **`brands.aliases` / `competitors` are JSON columns, not Postgres `ARRAY`.** The same model works on SQLite in tests. Rejected: ARRAY with a SQLite type decorator (more code for no gain at this size).
- **`env_ignore_empty=True` in settings.** A freshly copied `.env.example` contains blank lines like `OPENAI_API_KEY=`, which should mean "unset", not the empty string.
- **Docker host ports are configurable (`CITEWISE_DB_PORT`, `CITEWISE_API_PORT`, defaults 5432/8000).** Other local projects often already use 5432/8000.
- **The API container runs `alembic upgrade head` before uvicorn.** `docker compose up` works on a fresh clone without manual steps. Seeding stays explicit (`docker compose exec api citewise seed`).
- **Calls are priced by the requested model alias; `pricing.price_for` also accepts dated snapshots (`-YYYY-MM-DD` / `-YYYYMMDD` suffix only).** OpenAI returns resolved snapshot IDs. Exact-match pricing would record live calls as free and bypass the budget guard (found in code review). *Revised in review:* the original longest-`key-`-prefix rule would have priced a different model (`gpt-6-luna-mini`) as `gpt-6-luna`; only date suffixes are stripped now.
- **`JsonSchema` is checked for OpenAI strict-mode compatibility when it is constructed.** Mock mode would otherwise accept schemas the live API rejects with a 400 (`additionalProperties: false` and all properties `required`). `strict=False` is an explicit opt-out.
- **Responses that aren't `completed` (e.g. truncated) are returned to the caller but logged `ok=False` with full token cost.** They still bill tokens. The caller decides whether to retry. Rejected: raising (would lose the partial text and the token count).
- **Mock fixtures stay in `tests/fixtures/` (per CLAUDE.md) and ship in the Docker image.** `.dockerignore` re-includes `tests/fixtures`. The image sets `FIXTURES_DIR` / `BRANDS_DIR` explicitly instead of relying on the editable-install path.

### Module 0 review (2026-11-23)

- **Live mode fails closed on unpriced models (`UnpricedModelError`, raised before the call).** Cost 0 for an unknown model would make spend invisible and the Module 2 budget guard useless. A typo in `MODEL_*` would spend money without it showing up anywhere. Mock mode still allows any model, because it's free. Rejected: warn and record $0 (the previous behaviour); a nullable `cost_usd` (every aggregate would then need NULL handling).
- **The mock resolves `$ref`/`$defs` and prefers non-null `anyOf` branches.** Pydantic's `model_json_schema()` puts nested models in `$defs`. Without this, every nested structured output came back as strings in mock mode and failed validation. Rejected: inlining schemas by hand at each call site.
- **Brand fields are bounded and single-line at the API boundary.** They are max 20 aliases/competitors of at most 100 chars each, stripped, deduped case-insensitively, with no control characters. The domain is reduced to a bare hostname. These values are interpolated into every prompt from Module 1 on, so a newline is a prompt-injection vector and unbounded lists multiply cost. `BrandRead` has no input validators, so older rows can still be listed. Rejected: sanitising at prompt-render time only (Module 1 will also treat them as data, but rejecting bad input early is cheaper and clearer).

## Module 1

- **The mock embedder is calibrated feature hashing, not random vectors.** Stemmed words, char trigrams and bigrams are hashed into 1536 signed dims, and a reserved anchor dimension maps `cos -> 0.5 + 0.5 * cos`. Random vectors make every prompt equidistant, so offline dedup would drop nothing and clusters would be noise. The anchor only shifts the scale (rankings and clusters are unchanged), so paraphrases land above the production dedup default of 0.92 and related-but-different questions land below it, roughly like `text-embedding-3-small`. Rejected: per-purpose fake vectors (no structure); a local sentence-transformer (a ~100 MB download in CI, against "no network").
- **Mock answers for the panel are hand-written sources plus a recorder, not hand-edited fixture files.** `tests/fixtures/panel_source/<brand>.yaml` holds what the LLM "said": generated prompts per cell, the intent a careful labeler gives each one (`label:` where the generator drifted, about 9%), and topic labels keyed by each cluster's most central prompt. `scripts/record_panel_fixtures.py` runs the real pipeline and writes `mock_chat/<key>.json`, and `test_recorded_fixtures_are_current` fails when they go stale. Rejected: hand-editing hashed fixture files (keys depend on rendered prompts, so they break on any template change); keyword-matched topic labels alone (tried, and several clusters got the wrong theme).
- **Templates are Jinja with a `=== user ===` split, a `| data` filter (JSON-encoding) and `StrictUndefined`.** Brand fields and prompt texts are injected as JSON strings, so a newline or quote can't start a fake instruction block. A missing variable raises instead of rendering an empty string into a live prompt. The version (`panel/generate.v1`) is the template path, stored per prompt for Module 6 A/B tests. Rejected: Python f-strings (no versioning, easy to inject).
- **Generation makes one call per intent x persona (5 x 3 = 15 calls of 20 prompts), and the funnel stage is labeled by the model.** This gives balanced coverage without 45 calls for the full intent x persona x stage grid. Personas are a new `brands.personas` column, capped at 6 to bound cost.
- **Dedup is greedy and shortest-first, also against stored prompts, with exact duplicates (case, spacing and trailing `?!.` normalised) caught first by a unique `(brand_id, text_hash)`.** Shorter phrasings are usually how people actually type. Checking stored prompts makes `generate` and `import` idempotent. Dropped prompts are counted and logged, not stored. Rejected: connected-component dedup (one long chain of paraphrases would collapse unrelated ends).
- **Cluster on 20-dim PCA, and pick k by cosine silhouette within 6–14.** In 1536 dims distances concentrate, so the silhouette curve was flat and noisy (0.09–0.22) and always chose the smallest k. After PCA it separates better. The range is a product prior: ~300 prompts read best as 6–14 topics, and the curve is still too flat to trust silhouette alone. Both are settings. HDBSCAN uses scikit-learn's built-in implementation (no extra dependency), and noise points go to the nearest centroid so every prompt has a topic. Rejected: UMAP before clustering (an extra heavy dependency and non-deterministic across platforms; it stays optional for the report plot only).
- **All LLM calls in `cluster` run before any DB write.** Found in end-to-end testing: on file SQLite, the call tracker's separate session hit "database is locked" while the clustering transaction was open. On Postgres the same pattern would hold row locks across minutes of LLM latency.
- **Intent labels: the LLM is the teacher, and logistic regression on embeddings is the cheap student.** `eval-intent` reports 5-fold cross-validated agreement, so no prompt is scored by a model that saw its label, plus scores on a held-out hand-labeled golden set. Prompts the LLM couldn't label fall back to the embedding classifier, then to the intent the generator was asked for. `intent_source` records which one applied. Prompts that already have an intent are never re-sent, so re-clustering is free. LLM-vs-golden is skipped in mock mode because recording golden answers from the golden labels would report a fake 100%.
- **Panel selection covers every topic first, then fills seats proportionally with Sainte-Laguë over topic x intent cells.** Coverage is what Module 2 needs (a topic with zero scanned prompts has no visibility number). D'Hondt was tried first and gave small cells nothing (a cell with a fair share of 0.8 seats got 0). Selection is deterministic per seed, and `in_panel` is a flag on prompts. Rejected: a separate `panels` table (one active panel per brand is enough until Module 6 experiments).
- **Re-running `panel generate` skips cells already generated with the same template version (`--force` overrides).** Live output differs on every call, so a blind re-run would pay again and grow the panel without limit (found in code review). Text-hash uniqueness only stops identical rows. A new template version (`--version v2`) generates fresh cells, which is how prompt A/B tests will add to a panel.
- **Provider errors inside `complete_structured` count as a failed attempt; they don't crash the run.** A 429 or timeout on cell 12 used to roll back the 11 cells already paid for. Now the caller's fallback runs (skip the cell, fallback label, embedding classifier), and the `llm_calls` row still records the error. `UnpricedModelError` still propagates, since it is a configuration error caught before anything is spent.
- **Per-command spend cap (`BudgetedChatProvider`, `--max-cost`, default `MAX_COST_USD_PER_RUN`).** It adds up the estimated cost per chat call and refuses new calls once the cap is reached. A refusal turns into a skipped call (not a retry), so the run finishes with what it has and says how many calls were skipped. Embeddings aren't counted (about 1/1000 of chat cost at panel sizes). Module 2 will reuse this for scan runs. Related caps: `PANEL_IMPORT_MAX_ROWS` (5000) and a sampled silhouette (`PANEL_SILHOUETTE_SAMPLE`), because full silhouette is O(n²) in memory.
- **Templates are split at the marker line in the template source, before rendering.** Otherwise an interpolated value containing `=== user ===` could move the system/user boundary (code review, High). The category is `| data` (JSON) everywhere, and brand fields reject `===`.
- **Only teacher labels (`llm`, `import`) are kept for good and used for training.** `fallback` and `embedding` labels are retried with the LLM on each `cluster` run, so a transient outage doesn't freeze guesses, and the student is never trained on its own outputs.
- **Re-clustering clears `in_panel`.** The panel was stratified over the old topics, and `build` refuses to run while any prompt lacks a topic or intent.
- **Mock clusters were verified identical on Linux.** The full suite ran in a `python3.12-bookworm` container from a clean `git archive` (the CI checkout), and the fixture-currency tests passed. Silhouette scores for k=11 vs k=12 differ by only 0.005, so a future scikit-learn or BLAS change could flip k. If so, the staleness test fails loudly and the fix is to re-record.
- **The panel report is written to `evals/reports/`, not `reports/`.** CLAUDE.md's repo layout puts committed reports there, and the spec's `reports/` path predates that layout.
- **Search volume is out of scope. With real data:** join panel prompts to a clickstream or search-panel source (e.g. Google Ads Keyword Planner volumes for the nearest keyword, or a licensed AI-prompt panel like Profound's), map each prompt to its nearest keyword cluster by embedding, and weight share of voice by estimated volume per topic. Without such data, every prompt counts equally, and the README says so.

### Module 1 review (2026-11-23)

- **Every stored embedding records its vector space (`prompts.embedding_model = "<provider>:<model>"`), and stale vectors are re-embedded rather than rejected.** Mock and live share a model name but not a space, so the provider has to be part of the identity. Re-embedding a panel costs well under a cent, so silently fixing the vectors beats making the user run a migration step. `cluster_brand` refuses mixed spaces when it has no embedder, so a library caller can't get wrong clusters by accident. Rejected: refusing to run when spaces differ (bad UX for the documented mock → live path); keeping one embedding column per model (unneeded until we compare embedders).
- **`citewise panel reset <brand>` deletes that brand's prompts and topics, with a confirmation prompt unless `--yes`.** It is the clean way to rebuild a panel, e.g. before the first live run on a DB that holds mock prompts. The `llm_calls` cost history is kept on purpose: it is an audit log, not panel state.
- **The CLI forces UTF-8 on stdout/stderr (`errors="replace"`).** Windows pipes default to cp1252, and prompts and labels are user and LLM text in any language. Rejected: telling users to set `PYTHONUTF8=1` (easy to forget, and it fails after the DB commit).

## Module 2

- **Provider API shapes were checked against official docs on 2026-11-23 (api-docs-checker agent), and the async surfaces against the installed SDKs.**
  - OpenAI uses `{"type": "web_search"}` (`web_search_preview` is legacy).
  - Anthropic is pinned to `web_search_20250305`: the 2026 versions run search inside code execution by default, which changes the content blocks.
  - Gemini uses Google Search grounding. Its sources are `vertexaisearch` redirect URLs, so the citation domain comes from the title.
  - Perplexity moved to its Agent API (`/v1/responses`, OpenAI-compatible, model `perplexity/sonar`). Sources come from the `search_results` item plus `[web:N]` markers, and it reports its own cost, which is used.
  - Rejected: one generic "OpenAI-compatible" adapter for every engine. Citations and search billing differ per provider.
- **Default Gemini model `gemini-3.5-flash-lite`, not 3.1.** The grounding page doesn't list 3.1 Flash-Lite as supported, although the pricing page lists grounding fees for it. When the docs disagree, use the model both pages support.
- **SDK clients use `max_retries=0`; the runner owns retries.** This gives one retry policy (full-jitter exponential backoff, a capped attempt count), and every attempt lands in `llm_calls`. With nested SDK retries, the backoff would multiply and attempts would be invisible.
- **The mock engine is a deterministic simulator over a fictional world file, not a recorded fixture per answer.** 50 prompts × 4 engines × 2 brands is 400 texts, too many to hand-write. The simulator's per-engine bias makes share of voice differ by engine, and its true and false brand claims give Module 4 something to catch. A recorded `mock_engine/<key>.json` still overrides it. Rejected: one canned answer for everything (Module 3 metrics would be flat).
- **Cost = tokens at model price + per-search fees (or the provider-reported cost).** Search fees dominate a scan: about $0.01 per search vs about $0.001 in tokens per answer. Gemini's 5,000 free queries a month are ignored, so estimates err high. A full 50 × 4 scan is estimated at about $2.71, using a per-engine expected search count.
- **Budget guard = estimate before, reservations during.** Each call reserves its estimated cost before it is sent, so concurrent calls can't jointly overshoot the cap by more than estimation error. Billed failures count too: a rejected response is charged what it reports, and a timeout or cancelled call is charged its estimate, because the request may still bill. The run's cost is `SUM(llm_calls.cost_usd)`.
- **One executor per run (a lease).** `runs.heartbeat_at` is refreshed as answers land and is taken with an atomic conditional `UPDATE`. A second process gets `RunLeasedError`, the lease expires after 2 minutes, and `scan resume --force` takes over after a crash. Rejected: Postgres advisory locks (no SQLite equivalent for tests) and `SELECT ... FOR UPDATE` (held for minutes across LLM calls).
- **The run plan is frozen on the run** (prompt ids, engines, model IDs, system prompt), and answers keep `prompt_text`. Resume finishes exactly the planned work. `answers.prompt_id` is `ON DELETE SET NULL`, because answers are the historical record that trends are built on, and rebuilding a panel must not delete them.
- **Same-day cache key = sha256(mode, engine, model, system prompt, prompt, UTC date).** The mode is included because mock and live share model IDs; without it a live smoke test could "pass" on mock answers (found in review). Cached copies are $0 with zero tokens, and `cached_from_id` points at the source.
- **Mock mode disables rate limiting.** Perplexity's 1 request/s alone would make a 50-prompt mock scan take 50 s, against the 10 s acceptance target. Live mode limits are per engine (`SCAN_RATE_PER_S`).
- **API scans run as a sync background task (Starlette's threadpool, its own event loop).** The runner's DB writes are synchronous, and running them on the API's event loop would stall every request during a scan. Rejected: rewriting storage on async SQLAlchemy (two DB stacks for one table set).
- **Schedules live in a `schedules` table, and `citewise worker` syncs APScheduler jobs from it every minute.** The CLI and API can manage schedules without touching APScheduler's job store. `max_instances=1` and `coalesce=True` mean no overlapping runs and one catch-up run after downtime. APScheduler is pinned to 3.x, because 4.x changed the API.
- **Smaller scans take a stratified subset of the existing panel, and only a larger scan rebuilds it.** Trend comparisons need the same questions week to week. Rejected: rebuilding the panel whenever `--size` changed (a scheduled 20-prompt run would keep reshuffling the 50-prompt panel).
- **Per-answer timeout = `LLM_TIMEOUT_S` × 3 + 10 s.** An Anthropic answer can take up to 3 sequential requests (`pause_turn`), each with the SDK timeout.
- **Empty and truncated answers are failures, not answers.** Module 3 would count them as "brand not mentioned" and skew share of voice. Deterministic truncations (token limits, refusals, safety blocks) aren't retried.
